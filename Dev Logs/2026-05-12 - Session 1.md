## Decisions and surprises

- **Toolchain check:** `go 1.26.3`, `node v22.18`, `bun 1.2.3`, `pnpm` all present. Good.
- **No PostgreSQL daemon yet running.** Plan: tests use SQLite in-memory (works with GORM via `gorm.io/driver/sqlite`). For real DB I'll spin up Postgres via docker-compose later. Migrations written in Postgres flavor with SQLite-compatible subset where possible (use `TEXT` over `VARCHAR(n)`, `JSONB` → `TEXT` in SQLite path).

  Actually a better call: write GORM models with tags, let GORM do AutoMigrate for SQLite tests, and ship `.sql` migrations for Postgres prod. Two paths, one schema source-of-truth (the structs).

- **Asynq dropped from v1** — in-process goroutine for DNS verifier is enough and avoids Redis-as-queue complexity. Documented in 04.

- **Design folder uses `unpkg.com/react@18.3.1` via Babel-in-browser** — pure prototype. Visuals only; we re-implement properly in Next.js.

### 09:35 — Auth subsystem live
- Argon2id password hashing (default params: m=64MB, t=3, p=4, 32-byte key, 16-byte salt)
- HS256 JWT with explicit `alg` allowlist (no alg=none confusion)
- Refresh-token rotation chain stored as SHA-256 hashes; reuse triggers chain revocation
- OTP: 6-digit, hashed-at-rest, 10-min TTL, 5-attempt cap, atomic-consume via `UPDATE ... WHERE consumed_at IS NULL RETURNING ...`
- HttpOnly + Secure + SameSite=Lax cookies (`osm_access`, `osm_refresh`)
- Constant-time login error response (same code/message for unknown user vs wrong password)
- Dev-only OTP echo on register response — gated by `OSM_DEV_EXPOSE_OTP`, never true in prod

### 09:45 — Business logic complete
- **Domains:** create (with FQDN regex validation, plan-limit check), list, get, delete (cascades subdomains), force-verify endpoint
- **DNS Verifier:** in-process goroutine pool, `Resolver` interface so tests inject a fake. Checks CNAME == proxy target + TXT token at `_osm.{fqdn}`. Falls back to apex TXT-only.
- **Devices:** create (one-time API key shown), list (computes online status from `last_seen_at`), revoke (clears bindings + nukes Redis keys), heartbeat (Bearer auth)
- **Subdomains:** create (validates prefix + port, requires verified parent domain), list, bind/unbind with **Postgres+Redis transactional write** (Redis fail → Postgres rollback), emits WS events on every binding change
- **Admin:** network stats, paginated users list, user dossier, impersonation (short-lived JWT with `impersonated_by` claim, audited under both IDs), audit log viewer
