## Bridge styles

The bridge is how osmBroker talks to the child process.

- **`stdin` bridge** — osmBroker spawns the CLI binary and pipes the prompt in via `stdin`. The CLI writes streaming output to `stdout`. Simple, works for ~70% of CLIs.
- **`socket` bridge** — osmBroker connects to a unix socket the CLI opened. Used for CLIs that prefer JSON-RPC over an out-of-band channel.
- **`stdout` bridge** — osmBroker spawns the CLI and consumes its `stdout` only. Used for one-shot CLIs that don't accept ongoing input.
- **ACP (Agent Client Protocol)** — JSON-RPC over a long-lived stdio pipe. Standardized by the ACP working group. Used by Devin, Hermes, Kimi, Kiro, Kilo, Vibe.
- **Pi RPC** — Pi's bespoke protocol for talking to its router.

osmBroker handles the translation in both directions: prompt → bridge-specific input, bridge-specific output → OpenAI SSE delta frames.

## Which models each CLI serves

Click the **Models** tab in osmBroker. Each CLI shows its enabled model IDs:

![osmBroker Models tab — Claude Code's 3 enabled + Codex CLI's 4 enabled](/screenshots/osmbroker/models.png)

You toggle individual models on or off. Only models toggled **on** appear at `/v1/models` and accept inference requests.

<Callout type="info">
  Some "models" are upstream aliases (`sonnet`, `haiku`, `opus`) that auto-track Anthropic's current models. Others are specific versioned IDs. See the [PR](https://github.com/junainfinity/osmBroker) for details on each adapter's discovery logic.
</Callout>

## Adding a CLI not on this list

osmBroker is open to PRs adding new adapters. Each adapter is a Swift type conforming to a small `AgentAdapter` protocol — see `Sources/osmBrokerCore/Detection/AgentRegistry.swift` for examples.
