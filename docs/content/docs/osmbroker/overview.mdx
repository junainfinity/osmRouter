osmBroker is a separate Mac app that lives next to osmRouter. It speaks the OpenAI Chat Completions API on a local port, and routes each request to the right underlying CLI based on the requested model ID.

![osmBroker Serve pane — Live, base URL, API key](/screenshots/osmbroker/serve.png)

## Why this exists

LLM CLIs like Claude Code, Codex, Gemini, opencode, Devin-for-terminal, etc. are extraordinary inference engines wrapped in dev-focused interfaces. They're tuned for *coding workflows* — but the actual inference they do is the same Anthropic/OpenAI/Google API you'd hit from a library.

The problem: every CLI speaks a slightly different wire. Some pipe over `stdin`. Some open a unix socket. Some implement ACP JSON-RPC. None of them speak the OpenAI Chat Completions API that **every** client app (AnythingLLM, Open WebUI, LiteLLM, OpenAI Python SDK, the OpenAI JS SDK, etc.) expects.

osmBroker:

1. **Aggregates** every locally-installed agent CLI (16 supported today, see [Supported CLIs](/docs/osmbroker/supported-clis)).
2. **Translates** each one to OpenAI Chat Completions shape on the wire.
3. **Serves** the whole catalog at a single local port (`http://localhost:8080` by default), with one shared API key.

Pair it with an osmRouter tunnel and you've got a public OpenAI-compatible HTTPS URL that runs inference on hardware you own, charged by *your* underlying API keys (your Anthropic key, your ChatGPT plan, your Ollama process), and reachable by every standards-compliant client app on earth.

## When to use osmBroker

Use it if you want to:

- Expose Claude Code or Codex to **any OpenAI-API-compatible client** (AnythingLLM, Open WebUI, etc.).
- Build an internal "LLM router" without paying for a managed provider.
- Run open-source models locally (Ollama, LM Studio) and have them answer to the same endpoint as your paid Anthropic/OpenAI usage — fall back automatically based on cost or latency.
- Stand up an OpenAI-API mirror on your own hardware for use inside an air-gapped network.

Don't use it if you just want to pipe data through one CLI — call the CLI directly.

## Quick architecture

```
your client app (AnythingLLM, Open WebUI, …)
   │ POST /v1/chat/completions   { model: "sonnet" }
   ▼
osmBroker  ── classifies the model → routes to Claude Code CLI
   │ spawns: claude --model sonnet
   ▼
Claude Code CLI ── hits Anthropic API with your Claude key
   ▲
   │ SSE stream back, translated to OpenAI delta frames
```

For a different model ID (e.g. `gpt-5.5`), osmBroker routes to Codex CLI instead. The client app doesn't know — to it, this is just a list of OpenAI-style models.

  See [Supported CLIs](/docs/osmbroker/supported-clis) for the full list of CLIs osmBroker knows how to broker, and their wire styles (`stdin`, `socket`, `ACP`, `Pi RPC`).
</Callout>

## Combining with osmRouter

osmBroker on its own is **local-only** — it listens on `127.0.0.1:8080`. To expose it publicly:

1. Run osmBroker (Serve pane → **Start broker**).
2. In osmRouter, bind your verified domain to `127.0.0.1:8080`.

Now your public URL is an OpenAI-compatible endpoint backed by *your* CLIs running on *your* Mac.
